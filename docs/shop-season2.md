# 상점 시즌2 / 가챠

## 판매 전환

- 일반 상품은 기존 `typing_shop_items`에서 `season: 2`, `scope: 'school'`로 저장한다. 학급별 재고가 아닌 전교 공통 재고다.
- 이전 상품 문서는 삭제하지 않는다. 시즌2 조회에서 제외하고 서버 구매 API도 이전 시즌 상품을 거절한다. 기존 구매 기록과 보유 장식은 유지한다.
- 운영 DB의 기존 문서들을 일괄 수정하는 마이그레이션은 없다. 새 코드를 배포하면 이전 상품 판매가 종료된다.
- 기존 장식 목록은 관리자 지급과 기존 보유자 장착에 계속 사용한다. 새 일반 판매 상품은 교사가 등록한다. 가챠에는 장식/칭호를 넣지 않는다.

## 가챠 설정과 추첨

- 설정: `typing_settings/shop_season_2` 한 문서. `enabled`, `price`, `revision`, `stockRevision`, `prizes`, `defaultPrizeId`.
- 상품: `id`, `name`, `stock`, `weight`(100%=10000), `noReward`.
- 최대 40종, 확률 소수 둘째 자리 지원. 기본 상품을 제외한 설정 확률 합계는 100% 이하여야 한다. 운영 ON은 기본 상품 선택 후 가능하다.
- 최초 설정은 OFF, 기본 입력 가격 100P이며 교사가 가격/상품/확률/수량을 저장하고 ON으로 전환해야 한다.
- 품절 상품은 추첨에서 제외한다. 나머지 일반 상품의 설정 확률은 그대로 유지하며, 잔여 확률은 기본 상품에 자동 배정한다. 기본 상품은 수량 제한 없는 지급 없는 결과다. 기본 상품은 재고를 차감하지 않는다. 기존 `sold_out` 기록은 이력에서만 표시한다.
- 기본 상품은 교사가 '기본 상품으로 정하기'로 지정한다. 지정 시 지급 없는 결과로 바뀌고 확률은 자동 계산된다. 이전 설정에 defaultPrizeId가 없으면 기본 상품 선택 후 저장해야 뽑기가 가능하다.
- 효과음은 클릭 시 Web Audio로 합성한다. 손잡이 소리, 캡슐 배출/개봉 소리이며 음소거와 화면 이탈 시 정리를 지원한다. 음원 다운로드/DB 요청은 없다.
- 일반 상품과 가챠 상품 재고는 별도다. 다른 반 학생끼리는 동일한 가챠 재고를 사용한다.
- 서버 `crypto.randomInt`로 추첨한다. 클라이언트는 확률/결과/차감액을 결정하지 않는다.
- 서버 트랜잭션으로 포인트, 재고, 영수증을 원자적으로 반영한다. 설정 수정은 revision과 stockRevision을 검사해서 구매된 재고를 덮어쓰지 않는다.
- 학생별 요청 번호를 영수증 ID로 사용한다. 통신 오류/새로고침 후 같은 요청으로 재시도하면 재결제하지 않는다. 요청 번호는 결과를 받기 전 브라우저에 보관한다.

## 내역과 지급

- 기존 `typing_shop_purchases`에 시즌2 일반 구매와 가챠를 함께 보관한다.
- 가챠는 결과, 상품명, 확률, 설정 버전, 사용 포인트, 학생/학급 ID, 서버 생성 시간을 스냅샷으로 보관한다.
- `deliveryStatus`: `pending`(지급 대기), `delivered`(지급 완료), `not_required`(지급 없음).
- 교사 API만 지급 완료 처리 가능. 지급 완료 재요청은 중복 처리하지 않는다.
- 학생은 자신의 기록만, 교사는 전교 내역과 미지급 목록을 조회한다. 20건씩 더보기(다음 페이지 유무 확인용 1건 포함)이며 실시간 구독/폴링은 없다.
- 교사의 기존 학급별 최근 구매 정보도 수동 조회 방식으로 변경했다(학급 선택 시 최대 21문서 조회).

## 읽기 예산

- 가챠 화면 진입: 세션 1 + 설정 1 Read. 이후 대기/애니메이션 중 0.
- 새 뽑기: 세션 1 + 기존 영수증 1 + 학생 1 + 설정 1 = 통상 4 Read.
- 새 뽑기 Write: 학생 + 영수증 + 재고 변경 시 설정 = 2~3 Write.
- 트랜잭션 충돌/재시도 시 읽기 횟수는 증가할 수 있으므로 고정 비용 보장은 아니다.
- 일반 상점 구매도 응답의 남은 재고로 UI를 갱신하며, 구매할 때 전체 상품 목록을 재조회하지 않는다.
- 무제한 이용이므로 총 이용 횟수에 비례해 비용이 증가한다. 교사는 가챠 운영 OFF로 추가 뽑기를 중지할 수 있다.
- 자유 연습/게임 진행 로직에 신규 구독을 추가하지 않는다.

## 검증 및 배포

```sh
node --test tests/gacha.test.mjs tests/season-purchase.test.mjs tests/season-cosmetics.test.mjs
node tests/shop-browser.mjs
npm run build
```

- 트랜잭션은 모의 저장소에서 동시 요청/마지막 재고/중복 요청/권한/저장 충돌을 검증한다. 운영 Firebase에 구매를 발생시키는 테스트는 하지 않는다.
- 브라우저 테스트는 API 모킹으로 실제 UI의 애니메이션, 새로고침 복구, 모바일, 관리자 지급을 확인한다.
- DB 없는 체험: `/tests/shop-preview.html?demo=1`, 관리자 샘플: `/tests/shop-preview.html?demo=1&teacher=1`. Vite 개발 서버에서만 사용한다.
- 배포 전 `firestore.indexes.json`의 `typing_shop_purchases` 복합 인덱스를 배포하고 준비 완료를 확인해야 한다. Rules 변경은 필요 없다(서버 Admin SDK, 기존 교사 전용 설정 쓰기 정책 유지).
- 이 작업에서는 Git push, Vercel 배포, Firebase 인덱스 배포 및 실제 DB 변경을 수행하지 않았다.
